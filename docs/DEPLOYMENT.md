# Deploying AKSHARA (Vercel + Render)

The web app is static and runs on **Vercel**. The backend needs things serverless platforms
don't offer — LibreOffice for rendering, a background worker, a persistent disk for the
unchangeable originals, PostgreSQL and Redis — so it runs as a Docker service on **Render**.
Vercel forwards every `/api/*` request to Render, so the browser only ever talks to one origin
(the login cookie is `SameSite=Strict` and stays on your Vercel domain).

```
browser ──► Vercel (React app, frontend/vercel.json)
               └─ /api/* ──► Render web service "akshara-api" (API + Celery worker, one container)
                                ├─ Render PostgreSQL "akshara-db"
                                ├─ Render Key Value (Redis) "akshara-redis"
                                └─ Render disk /data/blobs (originals and renders)
```

## 1. Backend on Render

1. In the Render dashboard choose **New → Blueprint** and select this GitHub repository.
   Render reads [`render.yaml`](../render.yaml) and proposes the web service, the database and
   Redis. Review the plans (the web service uses `standard`, because LibreOffice needs more than
   512 MB of memory, and a 10 GB disk), then apply.
2. Wait for the first deploy. The container runs the database migrations, then the API and the
   worker. Check `https://akshara-api.onrender.com/api/v1/ready` — it should report
   `database`, `redis` and `storage` as `ok`.
3. If Render named the service differently (for example because `akshara-api` was taken),
   put its URL in `frontend/vercel.json` (the first rewrite) and push.

`AKSHARA_JWT_SECRET` is generated by Render. Never commit secrets.

**Optional features** (set in the service's Environment tab, then redeploy):

| Feature | Settings |
|---|---|
| AI editing, drafting and slide briefs | `AKSHARA_LLM_PROVIDER=anthropic`, `ANTHROPIC_API_KEY=…` (each user must also allow it in Settings) |
| Grammar | `AKSHARA_LANGUAGETOOL_URL=…` pointing at a LanguageTool server you run (for example the `erikvl87/languagetool` image as a Render private service with at least 1 GB of memory) |
| Reference checks | on by default; `AKSHARA_REFERENCE_LOOKUPS=false` turns them off |

If the service stops at start-up with `blob storage /data/blobs is not writable`, the disk is
not mounted at `/data/blobs` (check the disk's mount path).

## 2. Web app on Vercel

The Vercel project builds `frontend/` (Root Directory `frontend`, framework Vite, Node 22) and
deploys automatically on every push to `main`. All routing and security headers are in
[`frontend/vercel.json`](../frontend/vercel.json):

- `/api/*` is rewritten to the Render service, with Vercel's rewrite caching switched off and
  `Cache-Control: private, no-store`, so one user's API responses can never be cached for another.
- Every other path serves `index.html` (client-side routing).
- The same security headers and Content-Security-Policy as the Docker nginx config.

Deployment Protection (Vercel Authentication) is on for the project, so deployments are only
visible to members of the Vercel team until you turn it off under Settings → Deployment
Protection.

## 3. Check it

Open the Vercel URL, create an account, upload a document and wait for the preview. Large
uploads go through Vercel's proxy to Render; long work (rendering, checks, exports) runs in the
worker, so requests stay short.
